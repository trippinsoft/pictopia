# About this app

This file describes this app's stack, structure, and conventions. **Keep it updated and short**: when the app gains a backend, new conventions, or significant structure, edit this file (and the README) in place so future sessions inherit that knowledge. This file is loaded into every session, so it describes the current state only. Never add dated or per-task entries, change logs, or test results, even if earlier ones exist. Put notable decisions in `docs/HISTORY.md` as one line each, and keep this file under about 200 lines.

## Stack

- Expo cross-platform app (iOS / Android / Web), TypeScript (strict), Expo Router (file-based routing under `app/`)
- NativeWind (Tailwind for RN) for styling
- Yarn Berry (v4.x) — check `.yarnrc.yml` for the linker; with Plug'n'Play there is no traditional `node_modules`. Patching dependencies is a last resort; use `yarn patch`, never hand-edit.
- React Query available for server state when a backend is wired
- Path aliases are defined in `tsconfig.json` `paths` — use them instead of long relative imports.

## Theming

Keep colors and typography centralized in the app's existing theme setup (Tailwind config, theme files, or CSS variables) and use them through NativeWind classes — never hardcode per screen. When changing colors/typography, update the central definitions. Support both light and dark with readable contrast if the app supports both.

## Conventions

- **Reuse first:** use the app's existing component, icon, and styling libraries and patterns before adding new ones. Check `package.json` and existing components before introducing a dependency.
- **Icons:** use the app's existing icon approach. If icons need NativeWind classes, make sure they go through a wrapper or interop that applies them.
- **Navigation:** set an explicit human-friendly `title` for every screen header — never let route names like `(tabs)` or `products/[id]` appear in the UI. Keep `app/index.tsx` for redirects, not feature UI; use `_layout.tsx` files for stacks/tabs.
- **API routes:** server-only logic can live in Expo Router API routes (`+api.ts` files under `app/`). They require `web.output: "server"` in the app config and run in the preview; secrets they read use unprefixed environment variables, never `EXPO_PUBLIC_`.
- **Fonts:** load through the `expo-font` config plugin (declared in the app config) or `useFonts` in the root layout — follow whichever the app already uses.
- **Screens:** wrap in SafeAreaView (react-native-safe-area-context) and handle scrolling/gestures correctly. Keep bottom tab bars compact — pad content inside screens, not via `tabBarStyle`.
- **Components:** keep components small and focused, follow the app's existing folder structure, and reuse before creating.
- **Performance:** `FlatList`/`SectionList` for long lists — never `ScrollView` + `.map()` for large collections.

## Draftbit starter structure (if present)

Apps created from the Draftbit starter ship with the pieces below. Follow them where they exist; don't add them to apps that don't have them.

- **Theming:** `theming/ThemeProvider.tsx` injects theme objects (colors + typography) as CSS variables via NativeWind's `vars()`; typography is flattened (`h1.fontSize` → `--h1-fontSize`). Theme shape in `theming/Theme.ts`, concrete themes in `theming/themes/light.ts` and `dark.ts`, mapped to classes (`text-foreground`, `bg-background`, `text-h1`, `border-border`, …) in `tailwind.config.js`. `lib/useColorScheme.tsx` syncs the system preference. Use `useTheme()` only for raw values; change colors/typography in the theme files.
- **Components:** React Native Reusables (shadcn-style, `@rn-primitives/*`) in `components/ui/`, layout pieces in `components/layout/`, `cn` helper in `lib/utils.ts`. Build higher-level components on these primitives. Without `components/ui/` and `@rn-primitives/*` in `package.json`, compose React Native primitives with NativeWind instead and don't pull `@rn-primitives/*` in unless asked.
- **Icons:** `lib/icons/LucideIcon` wraps Lucide so NativeWind classes apply — `<LucideIcon name="Home" className="h-6 w-6 text-foreground" />`. Don't import from `lucide-react-native` directly, and validate `name` against the wrapper's registry.
- **Portals:** web uses `WebPortalContext`, native uses `PortalHost` from `@rn-primitives/portal`, both set up in `app/_layout.tsx`; the `components/ui/` primitives rely on them.
- **Alias:** `~/*` maps to the project root, e.g. `import { useTheme } from '~/theming/ThemeProvider';`.

## Current state

- Pictopia photo/video cleanup app; no backend/account needed. Expo SDK 55, React Native 0.83, iOS 15.1+ and Android API 24+ configuration.
- **Adventures.** Tabs are Home | Explore | Settings. **Home** (`app/(tabs)/home.tsx`, Pictopia chooses): branding, one or two illustrated choices (thematic art, title + truthful hint, no photo previews; Continue · n of N when started), “Show me two more” (a full new eligible pair; started choices move to Continue), two distinct browser choices from real selected files when themed plans do not fit, including previously explored files when needed (queued photos excluded), and one Journey line (distinct photos explored · set aside → `app/set-aside.tsx`). **Explore** (`app/(tabs)/explore.tsx`, the user chooses): Time Machine (`app/time-machine.tsx`, year/month list), On This Day, Surprise Me (detour), Screenshot Sweep — each shown only when the library supports it — plus Continue for unfinished chosen ones; `app/adventure-choose.tsx` redirects there. Adventures open `vertical-explore?adventure=<id>` on the existing scoped black Adventure theme and finish explicitly with Done on `adventure-finish.tsx` (closing line, distinct explored/set-aside counts, Home/Explore/Lab, occasional feedback; never Lab feedback).
- **Curation engine** (`lib/pictopia/curation.ts`, pure, tested in `tests/adventures.test.cjs`): `planCandidates` (month index → capsule/year/day/screenshots/detour/corners plans), `curate` (eligible photographs only, except explicit screenshot cleanup; quick series within 90 s collapse to the best-scored shot; unexplored/undecided first; kind-specific spread and sequencing: chronological for time kinds, oldest-first screenshots, year-alternating `twist` for detours, series kept together in corners; On This Day widens exact → ±3 → ±7 days → month, earlier years only), weighted 0–1 scores (`CURATION_WEIGHTS`: discovery, coherence, variety, cleanup, effort, personalization) with reasons, and `choosePair` (combined score minus similarity). Hints/titles use dates, screenshot flags, timestamps and scan data only — no location, people or scene data exists. `ADVENTURE_SIZE` 18, `OFFER_MIN` 10 (`lib/pictopia/adventures.ts`). Diagnostics are stored on each Adventure.
- `services/adventures.ts` persists `adventures:v1` (Home `slots`, `parked` = unfinished off-Home Adventures shown in Explore's Continue, `started`, `recent`, `finished`/`askedAt`), `adventure:<id>` metadata, `adventure:<id>:explore` sessions, `adventureFeedback:v1` (likes and Lab 1–5 ratings → per-kind affinity) and `adventureLab:v1`. Old 100-photo Home slots are retired once (`curated` flag; started ones move to parked). IDs are frozen at creation; Home refills a finished slot with the best partner for the other. `journey()` reports distinct explored / decided / set aside / queued / verified deleted / bytes from verified deletions (Settings "Your journey"). Adventure creation never decides or deletes. Review mutations in `services/explore.ts` atomically save the session and media queue decision using `storage.put`, the repository serializer and `deletionGuard`. A record’s `queued` flag mirrors the canonical media decision on load; restores and verified deletions elsewhere clear badges. Legacy `discarded` marks without `queued` stay preserved and are never auto-enqueued. Only the explicit queue confirmation invokes OS deletion.
- **Adventure review:** `components/pictopia/adventure-review.tsx` composes `ExploreFeed`/`ExploreCard`/`ExplorePager` with `review-actions.tsx`, `review-trash.tsx`, `discard-flight.tsx`, `discard-tray.tsx` and `review-hint.tsx`. Session v2 has `review: true`. Navigation is vertical scrolling plus sideways discards only; there is no thumbnail filmstrip. A marked photograph leaves the sequence (`exploreFeed` drops `queued` ids) and lives in the trash until it is restored or confirmed; legacy adventure-only marks are not deletions and stay in the sequence. Either sideways gesture marks deletion and moves to the next unmarked photograph, then the nearest earlier one; when everything is marked the screen says so and still offers the trash, Undo and Done. Only Done finishes (`finished: true`) — running out of photographs never does, and `adventureComplete` follows that flag. Zoom still uses the existing pinch/double-tap/pan architecture. The quiet ellipsis menu provides accessible Previous/Next/Mark/Undo, the trash and the confirmed deletion queue. Browsing only records distinct actually shown photos; it never writes Keep.
- **Discard flight and trash:** the swiped photograph is handed to the `discard-flight.tsx` overlay at the frame and offset the finger left it, and the card stops drawing it only once the flight is painted, so one picture travels continuously. `lib/pictopia/flight-math.ts` (pure, worklet-safe, tested) builds a quadratic Bézier that carries on in the swipe's direction, curves into the trash and shrinks to a ~38 pt miniature over 400–550 ms (a faster flick reaches further and flies shorter); reduced motion gets a 160 ms fade in place. Input unlocks as soon as the handoff lands, so the next photograph is swipeable while the previous one is still flying and its save is still queued; several flights can be in the air, each tied to its own photograph. `review-trash.tsx` sits beside Favorite and Share, reports its centre for flights to aim at, bounces on arrival (haptic when enabled) and counts `queued` records minus photographs still in the air. `discard-tray.tsx` is the pending-discard sheet: a horizontal carousel of this adventure's marked photographs, tap to inspect, Restore for the selected one. The tray, the immediate Undo and the deletion queue all read and write the same queue decisions — never a separate list.
- **Review guidance:** `reviewGuidance:v1` persists browse/discard/trash/restore/actions steps independently. Non-blocking hints use actual review events, have Next tip/Skip controls, screen-reader announcements and reduced-motion cues. Help (reachable from Settings) resets the steps. No hint makes a media decision, and no step requires discarding or restoring a real photograph.
- **Pit Stops** (`app/pit-stops.tsx`, `app/pit-stop.tsx`, `lib/pictopia/pitstops.ts`, `services/pitstops.ts`): discoverable in Explore; Guess the Year and Which Came First use native capture dates, Memory Match uses six real photos on all platforms; a mismatched pair turns back by itself (1.2 s, 3 s with a screen reader). Where Was This stays disabled because locations are not read; browser modified dates never power quizzes. Games are read-only, handle unavailable photos, and offer a chosen Adventure of the played photos afterward. Which Came First alone uses stacked photo targets sized to each photo’s aspect ratio, sharing height one photo doesn’t need with the other (`orderPhotoFrames`; instructions live in the feedback line), tap-to-answer with date/correctness/“Your pick” overlays, per-photo pinch/pan/double-tap zoom to 3× clamped inside each frame (`components/pictopia/zoom-choice.*`, math in `lib/pictopia/zoom-math.ts`; only a still single tap at 1× answers), and a cancellable 1.8-second advance; screen readers advance manually. No game writes production decisions or deletes.
- **Photo eligibility:** `lib/pictopia/photo-eligibility.ts` is shared by curation and Pit Stops. Ordinary adventures (including Hidden Corners/Lab) and game-review adventures exclude identified screenshots before sampling; Screenshot Sweep opts in. Both storage adapters apply `screenshot: false` before limits and `months(true)` supplies photograph-only capacity. Legacy mixed snapshots are retired intact, preserving Journey/restore history. iOS reads PhotoKit subtypes through Expo/the native module, including per-asset fallback; Android reads MediaStore screenshot directories (relative path on API 29+, parent path on 24–28) and screenshot albums. Names/dimensions alone never classify an image; exported or moved images may lack identifying metadata.
- **Adventure artwork:** `components/pictopia/adventure-art.tsx` maps kinds to optimized WebP art in `assets/images/adventures/` (600 px wide covers, 1200 px wide finish headers). On This Day, Time Machine (year/month), and Detour (including the browser library choice) use photorealistic background plates without blank photo frames; independent white-bordered cards overlay real saved photo IDs, preserve each photo's portrait or landscape aspect ratio without cropping, and are omitted when files are unavailable. Detour's cover stacks up to three distinct photos. The other Adventure kinds retain their existing painted art or SVG illustrations. Duplicates art is reserved for a future Duplicates Adventure kind. Art files contain no user photos; browser files are resolved locally, and native photos use their library URIs.
- **Illustration system:** theme-aware SVG metaphors in `components/pictopia/illustration.tsx`, palette in `theming/illustration.ts`, shared rows in `art-list.tsx`. Home, Explore, Time Machine, Pit Stops and completion share these assets. Entrance/refresh animations respect system reduced motion; photo feed gesture architecture stays independent.
- **Adventure Lab** (`app/adventure-lab.tsx`, developer-only, opened by long-pressing the version line in Settings): Detour (~15), Time Capsule and Hidden Corners experiments from real photos, frozen until Regenerate, with full diagnostics, Home's current pair diagnostics, and optional 1–5 ratings.

- Stack routes include adventure-lab, set-aside, vertical-explore, onboarding, full preview (with a Keep / Set aside bar for decided items), this session's photos (`session-review`), safe deletion queue, comparisons, Pro paywall, insights, help, and legal drafts.
- `components/pictopia/provider.tsx` coordinates permission, paginated sync, sessions, preferences, scan state, and current Pro entitlement. Repository mutations are serialized; read the latest asset inside the serialized mutation to preserve decisions during sync/analysis.
- `services/*.{native,web}.ts` share `.types.ts` interfaces and `.d.ts` declarations. Native uses Expo MediaLibrary and SQLite schema v1. Web uses real selected files and IndexedDB schema v1, with no original-file deletion or simulated store purchases. Browser dates are last-modified dates.
- `lib/pictopia/` holds typed records, calendar grouping, stable shuffle, decisions/undo, entitlement expiry, genuine quality heuristics, and Smart Session names/timing. Smart Sessions (Quick Wins, Memory Lane, Best of the Bunch; 2/5/10-minute batches) live in the classic Swipe flow.
- `modules/pictopia-analysis/` is an autolinked Swift/Kotlin Expo module: off-thread streaming original SHA-256, 32px difference hash/Laplacian variance, favorites/screenshot metadata, scan cancellation and resource checks. Requires a native build, not Expo Go. iOS Live Photo motion uses a native PhotosUI view; still preview and paired hashing also exist.
- Unfinished reviews resume before any new collection can start. Sessions may finish early; timer expiry never makes decisions.
- Swipe deck: `lib/pictopia/swipe-machine.ts` (pure reducer) + `deck-controller.ts` (watchdogs: settle 6 s, fly-out 700 ms, save 8 s) behind `components/pictopia/use-swipe-deck.ts`. Readiness is tracked per photo id and never reset by provider refreshes; controls unlock when the photo's media settles (loaded, failed placeholder, or timeout). Each `SwipeCard` owns its Reanimated values; the next photo renders underneath; buttons call the same fling as gestures. Physics in `swipe-physics.ts`.
- Review timer: `lib/pictopia/review-clock.ts` counts only while focused + AppState active + page visible + photo ready; `use-review-clock.ts` saves every ~4 s and immediately on blur/background. Provider decisions resolve on save; library totals refresh in the background.
- Native photos display straight from `media.uri` (`ph://` on iOS, which expo-image loads with iCloud access); `mediaService.resolve` is a fallback and is still used for video, analysis and file sizes.
- **Review native media:** `services/review-media.{native,web}.ts` uses `PictopiaReview` helpers in the existing autolinked module. iOS reads and writes PhotoKit `isFavorite` and re-reads after completion; Android 11+ uses `MediaStore.createFavoriteRequest` and verifies `IS_FAVORITE` after OS approval (not a Google Photos cloud guarantee). Earlier Android/browser builds report unsupported; no local substitute. Older classic-review app favorites remain separate. Sharing uses UIActivityViewController with a temporary original-quality resource export (removed after dismissal; unfinished exports cleaned on next share) or Android ACTION_SEND with a granted content URI and no copy. Live Photos share the still resource. Its 160 px thumbnail helpers remain in the module but no UI uses them now that the filmstrip is gone; review images all come from the existing nearby-page window. Native changes require Publishing; do not claim device validation from host tests.
- Legacy database identifiers and the Live Photo hash boundary marker remain stable across branding changes so existing cleanup data and cached hashes are preserved. Native identifiers are `com.trippinsoft.pictopia` on iOS (registered with Apple) and Android; changing them after release breaks store continuity and local data.
- Native media references are never copies of full-resolution originals. Marking is local only; deletion requires explicit confirmation and OS authorization. Storage numbers are estimates from known sizes, not measured free-space changes.
- Deletion safety (`services/deletion.ts`, rules in `lib/pictopia/deletion.ts`): only items verified visible and unchanged are sent to the OS; a `deletionAttempt` journal is persisted before the request and its OS result after; outcomes (confirmed / remaining / uncertain / skipped) and `confirmedCleanup` are applied in one transaction, processing only still-tracked ids so replays never double count. Absence proves deletion only under full access, or under limited access with a recorded OS success and unchanged scope; everything else goes to `deletionPending`. `recoverDeletions` runs at native startup, on foreground, and before each deletion; it never deletes. Decisions on items in an in-flight journal are refused; restoring/keeping a pending item stops tracking it. Verified deletions set `deletedAt` on the record.
- Swipe decisions and skips pass the displayed item id; the repository rejects them if the session has moved on.
- Copy uses Keep / Set aside / Restore / Delete consistently; counts go through `plural()` in `lib/pictopia/text.ts`.
