# Device acceptance matrix

All scenarios below are **not yet run on physical devices**. Use an internal native build from Draftbit Publishing, the registered test bundle/package IDs, and store sandbox accounts. Use disposable test media and a backup; never test deletion on the only copy of an important memory.

Repeat on minimum supported iOS/Android and a current maintained version; include a limited-access library, Android OEM variants, portrait/landscape rotation, large text, reduced motion, and screen readers.

| Scenario | Steps and required result |
| --- | --- |
| Navigation and accomplishments | Verify Home / Explore / Progress, the Progress gear and guarded Settings/history back actions on an iPhone. With a populated library, check two featured covers, actual collection thumbnails, one latest Continue, per-collection resume, lifetime versus current completion, completed months after imports/access changes, and pending versus confirmed cleanup. Repeat both themes with large text and VoiceOver; confirm vertical scroll, sideways discard, Undo and the queue retain their behavior. |
| Appearance | Switch Light/Dark/System on iOS and Android; change OS appearance while open and backgrounded, reload/force-quit, and verify headers, status/navigation controls, permission dialogs, loading states and deletion confirmation. Confirm no screen/session resets or white startup flash. Include three-button and gesture navigation. |
| First launch | Open a fresh install, use onboarding, reach permission explanation without a paywall or account. |
| Full / limited / denied access | Grant each mode separately. Only authorized actual media appears. Denial offers Settings; limited access remains usable. |
| Photos and videos | Import fixture media into device Photos. Verify counts, creation months, ordering, representative thumbnails, video duration, unknown-size labeling. |
| Keep | Swipe right beyond threshold. Exactly one current ID gets a keep decision; original remains. |
| Set aside | Swipe left beyond threshold. Exactly one ID enters the queue; original remains. |
| Threshold and rapid input | Short drag springs back; repeated taps/rapid reversals do not double-apply or skip an ID. |
| Undo and skip | Undo restores the prior decision and counters. Skip does not create a decision. |
| Smart Sessions | Try Quick Wins, Memory Lane, and Best of the Bunch at 2/5/10 minutes; validate actual prioritization and suggested keepers. Finish early, undo, resume, and verify all originals remain until authorized deletion. |
| Session timer | Start a 2-minute session; leave via home gesture, lock and app switcher; return after 10 s and after 5+ minutes; force-quit and relaunch. The timer resumes on its own when a photo is on screen, never counts time away, and keeps its place within a few seconds after relaunch. At zero, users may finish or continue; no automatic decision or deletion. |
| Review controls | Review 30+ photos mixing swipes, button taps and rapid double taps, including right after returning from the background. Keep / Set aside never stay disabled while a photo is visible; nothing is decided twice or skipped; cloud-only photos display or explain themselves with Skip available. |
| Swipe feel | Card tracks the finger, short drags spring back, committed swipes leave fully, the next photo is already in place, buttons animate like swipes, haptics follow the setting, and Reduce Motion replaces motion with quick fades. |
| Process death | Kill after each decision, restart and reboot. Session position and queue match committed database state. |
| Full preview | Pinch, double tap, pan, rotate; play/pause/scrub portrait and landscape videos. Cloud/unavailable items explain failure. |
| Queue | Preview, restore one, restore all. Queue counts and sizes update correctly; originals remain. |
| Cancel deletion | Cancel in-app confirmation and OS authorization separately. No success or recovered-space claim appears. |
| Confirm deletion | Approve deletion on a disposable batch. Verify original IDs absent from OS enumeration and app. Explain Recently Deleted/Trash. |
| Partial results | Remove one asset externally during review; revoke permission during request. Only verified deletions leave local active state; ambiguous items retain history. |
| Limited-access deletion | iOS "Selected Photos" and Android 14 "Allow limited access": queue items inside and outside the selection, then delete. Only selected items are sent to the OS; unselected items are reported as unavailable and remain marked. Cancel the OS sheet once and confirm the "Deletion cancelled" message. |
| Restored items | Set aside several items, restore one from the queue, and check the session summary, Home and Insights: the restored item no longer counts as set aside and reappears in a later session. After confirming a deletion, deleted items still count as set aside in that session. |
| Interrupted deletion | Force-quit (app switcher) while the OS deletion sheet is open, once before and once after approving. Relaunch: the app reports the checked result; full access confirms absent items once; limited access reports unverified items without counting them. Relaunch again: counts in Insights do not change. |
| Exact duplicates | Include byte-identical originals, visually matching re-encodes, and matching filenames with different bytes. Only content-hash matches form exact groups. Live Photos require matching paired content. |
| Similar / best shot / blur | Use controlled nearby captures, rotated/cropped frames, sharp and low-detail images. Compare suggestions manually; no automatic deletion. |
| Scan interruptions | Pause, cancel, background, low-power mode, low memory, thermal pressure, process death. Resume without re-hashing unchanged successful originals. |
| Screenshots / large videos | Verify supported screenshot metadata and largest known file ordering; cloud/unknown sizes stay honest. |
| Quick Clean | Free account can review 30-item batches indefinitely; favorites and reviewed items are excluded by preference. |
| Purchase plans | With real store sandbox, buy monthly, annual, and lifetime independently. Native localized price and authorization shown. Only confirmed `pro` unlocks features. |
| Pending / cancel / restore | Cancel checkout, use Google pending approval, reinstall/second device with same store account, restore. No false success. |
| Expiry / refund | Expire sandbox subscription, revoke/refund a test purchase. Refresh CustomerInfo; premium gates close without clearing history. Lifetime remains non-renewing. |
| Offline | Review/undo/resume offline. Active cached entitlements work until their actual expiration; store operations report unavailable rather than simulating success. |
| Accessibility | VoiceOver/TalkBack action labels, touch targets, large text, contrast in both themes, reduced motion, alternative tap actions. |
| Stress | Repeat with 100 / 1,000 / 10,000 / 50,000+ actual media. Measure peak memory, query latency, swipe frame pacing, scan cancellation latency, and impact of very large/cloud assets. |
| Native launch | Confirm icons/splash, OS minimum versions, tablet/rotation, permissions, signing, store product ownership, and custom-module loading. |

| Screenshot eligibility | On iOS confirm actual Photos screenshots have PhotoKit screenshot subtype; test module and Expo fallback. On Android test API 24–28 parent-path metadata and API 29+ relative paths, standard screenshot albums, and vendor devices. Confirm camera photos with screenshot-like names/dimensions remain eligible. Exported/moved files without screenshot metadata must not be claimed as reliably classified. |
| Screenshot-heavy libraries | In a library dominated by screenshots, verify full photo adventures and all three games contain only eligible photographs; Screenshot Sweep still selects screenshots. Screenshot-only libraries offer cleanup and gracefully disable photo games. Existing mixed offers retire with set-aside history intact. |
| Which Came First | Small and large iPhones plus Android portrait: two stacked targets that hug each photo’s shape and together fill the space between the progress bar and the one-line instructions/result (a landscape photo’s unused height goes to the other photo), no distortion or letterboxing, dates and result fit within safe areas without scrolling. Rapidly tap both cards: only one answer counts. Check correct/incorrect results, both dates, 1.8-second advance, skipped cloud failures, and final score. Back/background during feedback must not submit after exit or silently advance in the background. VoiceOver/TalkBack retain feedback until Next; verify large text, dark mode, and reduced motion. |
| Which Came First zoom | iPhone and Android: pinch each photo to 3× (no further), drag while zoomed — the photo never leaves its card or covers the other one. Double-tap zooms toward the tapped spot and back. None of pinch, pan, double-tap, two-finger touch, or a tap on a zoomed photo answers; a still single tap at normal size answers once. Zoom resets on the next question. Check near the left edge that iOS back-swipe still works, and that VoiceOver/TalkBack double-tap still chooses. |
| Review-state regression (iPhone build after the fix) | Open Time Machine (18). Scroll to 18 of 18, mark it → end card shows “End of 18”, no date, no heart/share. Undo → photo 18 returns; mark again; repeat 3×: trash count goes up by one only. Scroll back to 16, mark it → 17 of 18 shows, no “Couldn’t save your place”, no end card. Leave after 20+ photos or a mark: the recap card appears on Home/Explore for ~6 s (stays with VoiceOver). Zoom, Live Photos, video play/pause and favourites/share behave as before. Check safe areas, large text, reduced motion, VoiceOver/TalkBack and limited access. |
| Endings and deletion | From Completion → Ready to delete: tap keeps, long-press opens full screen, “Delete N photos” names the exact count. iOS: the system prompt appears; Cancel returns with “Nothing was deleted”; Delete shows the Result screen with “moved to Recently Deleted” and the items appear there. Android 10 and earlier: Pictopia's own confirmation appears first. Partial/uncertain outcomes (revoke access mid-request) show the right copy; Done returns to the review's origin. |
| Daily limit and Pro | With a test limit of 10: the limit page appears before the 11th new photo in any adventure, album, video or collection, an already-counted photo seen elsewhere doesn't count again, Undo/trash/deletion/✕ still work and nothing is completed. ## Unified Library Progress (physical iPhone, unexecuted)

- Use Publishing for the build. Browse loaded photos without deciding in an adventure and ordinary cleaning; hold the final photo for at least 400 ms without leaving it, revisit the same photos in both flows, and check each counts once. Background, lock or leave the screen before the dwell expires; offscreen/preloaded photos must not count. Check the full-photo preview too. Swipe rapidly past unloaded/iCloud photos and confirm they do not count as displayed.
- Relaunch, Undo and Restore: explored totals must persist. Queue and explicitly confirm a deletion; check pending versus confirmed and estimated known bytes, including recovery after interruption. Cancel OS deletion and confirm no deletion accomplishment is added.
- Add photos in Photos, remove seen and unseen photos externally, then foreground Pictopia. New accessible photos become remaining, explored accomplishments stay, externally removed photos do not become confirmed Pictopia deletions. Test limited access changes and permission denial; no temporary false percentage during sync.
- Alternate unfinished classic and adventure reviews; Home resumes the latest activity, Explore retains the other adventures, and ordinary cleaning stays accessible. Verify vertical scrolling, horizontal discards, Undo, restoration, VoiceOver and large text, light/dark mode and a large library.

## Full chronological collections (physical iPhone, unexecuted)

- Open a month containing more than 240 photos. Browse multiple 120-photo batches, switch to another month/screenshots/an adventure, relaunch and resume the requested collection. Verify photos with identical dates are neither omitted nor repeated in Browse all. Prior batches must remain available for review and Undo.
- Explore June photos through Surprise Me or full preview, then open Months & Years: June and its year must already have credit. Complete a month, import new photos into that month and verify it reopens with the correct remaining count. Check screenshots and Live Photo stills are included, videos excluded, and unavailable dates have a separate group.
- Delete explored photos through explicit confirmation, add unseen photos, and narrow/expand limited access. Primary percentage follows the current accessible library; lifetime explored persists. Empty access must not show 100%. Externally removed photos never become confirmed Pictopia deletions.
- Confirm unchanged vertical browsing, horizontal discards, flight/trash, Undo from completion and previous snapshots, restore from another experience/queue, OS cancellation and interrupted-deletion recovery. Verify iCloud/unavailable thumbnails, large libraries, VoiceOver, large text, small iPhones and both themes. Host tests do not substitute for these checks.

## Explore album and video layout

Check one, two and many albums, long names, and narrow/wide screens with large system text. In WhatsApp, test an unavailable first item followed by an accessible item, limited access, and no loadable cover: the illustrated fallback must never prevent opening the album. Verify full names in review headers and unchanged oldest-first/size video ordering. See the secondary Explore section of [the reliability investigation](PROGRESS_RELIABILITY.md). Native checks remain unexecuted.

## Consistent navigation and controls

- Verify upper-left Back beside the title across Help, Privacy/Terms, Pro, Settings, albums, calendar, Time Machine, Pit Stops, history, preview, comparisons and deletion screens. Long titles and large system text must wrap without hiding actions; headers remain reachable when body content scrolls.
- Test direct entry without navigation history: Back returns to the relevant Settings/Explore/Home destination. Help and legal pages must not show unrelated trash controls; cleanup screens retain the queue shortcut.
- Leave an active review/game with Back and Android system Back; saved position, recap and game cancellation must behave as before. Check completion exits, queue result dismissal and the Settings Done action. None of these navigation controls should complete a review or change a media decision by themselves.
- Check status-bar/Dynamic Island/home-indicator clearance on iPhone, modal Settings dismissal, narrow paywall price labels, disabled actions for unavailable previews and VoiceOver labels. Native checks remain unexecuted.

## Designed artwork consistency

Check Home offers, Explore catalog cards, Settings theme previews, all four Pit Stop menu entries and adventure completion: only the designed SVG illustration set should appear. Collection thumbnails, review media and game photographs must remain the actual library content. Verify that art loading does not record exploration or affect eligibility. Legacy scene image files are retained but must not be imported into UI.

## Badge flip details

Tap a badge on Progress: it enlarges in the center, then turns over to show the saved achievement facts. Verify See badge turns it to the front, tapping the front turns it back, and Done, backdrop, close and Android Back dismiss safely. Check short screens, long audit text, larger text, VoiceOver and Reduce Motion (details appear without scaling/rotation). Badge totals and awards must remain unchanged. Native animation/accessibility checks remain unexecuted.
