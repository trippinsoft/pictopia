# Pictopia

The welcome uses Pictopia’s illustrated photo pile and a larger wordmark on native phones. The story demos precede photo access. After the library count, onboarding shows the 5× Pictopia+ showcase, an eligible trial timeline with direct redemption and a View all plans bottom sheet, and one adventure reveal with sunrays before Home. The trial offer’s upper-left close appears after four seconds. People without a trial open the same bottom sheet to see paid plans. Pictopia+ members replaying onboarding can view plans and continue without a purchase. The offer is skipped for existing Pictopia+ members outside developer replay.

An eligible trial started during onboarding schedules one local reminder if notifications are enabled and an iPhone running iOS 17.2+ verifies the new StoreKit trial. Production uses the signed trial end date, with one day of notice for the three-day trial. Sandbox uses the same relative timing if the store accelerates the trial.

In development and opted-in staging builds, **Settings → Developer tools → Replay onboarding** reuses existing photo access and keeps photo progress, system permissions, and store history. Use [the Apple sandbox checklist](docs/SUBSCRIPTIONS.md#testflight-exercise-real-billing) for a fresh trial.

Keep the memories. Lose the clutter.

Subscriptions use direct StoreKit 2 / Google Play Billing through `expo-iap`, with no RevenueCat setup required. See [the subscription setup checklist](docs/SUBSCRIPTIONS.md) for exact product IDs, Apple configuration, TestFlight billing tests and release requirements.

Optional Amplitude analytics tracks app opens, foreground returns, fixed screen names and the Pictopia+ conversion funnel using a random installation identifier. Purchase/trial events require new verified StoreKit transactions and a persistent local deduplication ledger; lifetime awards and developer overrides never generate subscription purchases. Renewals while the app is closed require a separate authoritative server integration, which is not implemented. Set `EXPO_PUBLIC_AMPLITUDE_API_KEY` to the project's public API key and `EXPO_PUBLIC_AMPLITUDE_SERVER_ZONE` to `US` or `EU`; without a key, analytics stays off. No photos, media identifiers or route parameters are sent. Native SDK installation requires a new build through Publishing. See [ANALYTICS.md](docs/ANALYTICS.md) for events, privacy boundaries and verification.

Pictopia connects to the existing **Pictopia** Supabase project in **Data Systems Inc.** (`hvacjgfjmzxxirjxhkgl`) for installation-based referral rewards and disabled lifetime-entitlement infrastructure, using the public URL and publishable key in each environment. Each installation may redeem one code: both parties immediately earn 1,000 bonus photo/video reviews. Outgoing referrals are unlimited and credits never expire. Saved credits spend offline after the daily/streak pool; Pictopia+ never spends credits. Daily totals rise from 100 to 125/150/175/200 based on completed preceding streak days, capped at 200. Home’s gift icon and Settings open the single referral screen. No user accounts, emails, referral links or cloud photo storage. Photo access, review history and cleanup stay local. See `docs/REFERRAL_REWARDS.md` for recovery, server security, deployment source and device checks.

Pictopia is an Expo SDK 55 / React Native 0.83 application with a working browser review flow and native media-library, SQLite, local-analysis, and direct Expo IAP integrations. **It is not yet verified for commercial release.** Native build compilation, device photo-library/deletion tests, and genuine store sandbox purchases remain required.

## Home and Adventures

The tabs are Home, Explore and Progress. Home keeps one most-recent Continue action, a compact exploration ring, two featured adventures with existing artwork, and a single Explore link. Explore separates illustrated adventures from complete Months & Years, All Photos, Screenshots and Duplicates collections; local photo thumbnails are decorative and never count as exploration. Pit Stops is a permanent two-game section in Explore, and unfinished sessions resume through Home or their collection without a session-management list. Progress separates accessible-library completion, lifetime explored photos, completed accessible months, confirmed photo deletions, estimated cleanup and the reversible pending queue. Cleanup history keeps its existing Pro access rules. Settings opens through the Progress header gear; preferences, permissions, subscriptions, support and legal actions remain there. Existing subscription and review behavior is unchanged. No demo library is used. Home’s “Did you know?” note randomly rotates through 200 local facts, exhausting every fact before refilling and avoiding the last 50 across refills, advancing on tap or a later local calendar day. Home measures content independently of adaptive gaps so fact wrapping cannot feed spacing back into its own input; short screens and larger text retain natural scrolling.

One tap opens the vertical explorer: scroll vertically in either direction without making decisions, and swipe a photo sideways to send it to the trash — it flies out of your hand into the trashcan in the corner and the next photo slides into its place using the original 1.0.21 interaction. Discarded photos stay in their place in the feed, faded, with Restore ready, so “N of M” never jumps. Snapshot history and pending marks remain intact. The standalone Undo icon stays visible at the lower left, aligned with Favorite and Share, while there are discards or existing queue marks to restore and brings the last one straight back; tapping the trashcan opens a tray of everything this adventure has marked, where Restore puts a photo back exactly where it was. Screen readers can use photo actions for navigation, marking and Undo. Leave anytime and Home offers **Continue**. **Explore** is where you choose: The Yearbook (choose a year), On This Day, Surprise Me shown only when your library supports them. Screenshot Sweep snapshots remain supported without a duplicate Explore collection entry. Scroll forward beyond the final photo, or mark the final original photo, to finish an Adventure with a minimal summary: large Explored and Marked counts, one overall-progress line and bottom-aligned Continue / Finish for Now (Done at whole-scope completion). Pending marks never claim deletion or recovered storage. New discard marks enter the existing deletion queue atomically with session state; they never delete an original. The upper-right trashcan shows this adventure’s pending marks and a persistent red MB/GB total of known file sizes, with a brief pulse and fading size increment on additions; missing sizes are identified. Favorite and Share sit above the bottom edge. The trashcan count is this adventure's pending marks, the tray and the deletion queue are the same list, and actual deletion still requires explicit queue confirmation and OS approval. Older adventure-only set-aside marks are preserved without auto-enqueuing them. The Home percentage ring opens Progress. Persistent first-seen records count photos once across adventures, ordinary cleaning and full previews, independently of decisions. A loaded foreground photo counts immediately, even during rapid scrolling; preloads, failed loads and hidden screens do not. Qualified encounters survive delayed writes without moving the review, preserve the earliest timestamp through photo edits, and retry transient failures up to three times; persistent save failures are reported. Explored history includes removed photos; remaining counts only currently accessible unseen photos. The primary percentage is explored photos currently accessible divided by all photos currently accessible. Lifetime explored is a separate cumulative count that retains credit after removal. Changes in photo access can change the percentage and never count as cleanup; empty access is not shown as completed. Videos stay outside this photo-only percentage. Pending and verified deletions and estimated deleted-file size are separate. Native counts stay neutral until library sync succeeds. Existing saved encounters and choices migrate once; earlier browsing with no saved evidence cannot be recovered. A developer-only **Adventure Lab** opens when you long-press the version line in Settings. Development and opted-in staging builds also show **Developer tools** in Settings (Free / Pictopia+ / Automatic, a testing daily limit and a usage reset); Production builds ignore them.

Home, Explore, Pit Stops, Settings and Adventure completion share rich purple/orange sunset light and dark themes, bold Inter headings, the original text wordmark, and a theme-aware SVG illustration system; photo review alone uses the black Adventure theme. All decorative artwork uses the existing designed SVG illustrations, including Adventure covers, completion headers, catalog cards, theme previews and Pit Stop menus. No photorealistic scene artwork or personal-photo overlays decorate these surfaces; real user photographs remain in collection thumbnails, reviews and games. Legacy raster artwork is retained as unused source material. The stored Home offers retain their existing identities; the underlying pair-refresh API remains available without a Home control. When imported photos match no themed Home plan, Home offers a truthful selection from the available library. In the browser, it offers two different choices from selected files even when there are fewer than ten or those photos were explored before; queued and deleted photos stay out. Small selections may appear in both choices. Equal browser file modification timestamps never collapse separate files into one burst. Smaller native libraries can still choose an Adventure in Explore. Entrance animations respect reduced motion.

**Pit Stops** are Memory Match (Easy: four pairs; Standard: six) and Which Came First? (up to ten comparisons using distinct, reliably dated photos). Explore exposes both directly. Games use existing thumbnails/display loading and never alter originals, pending deletions, Adventure exploration, or Free review usage. Each has Play Again / Done. Which Came First? places photos side by side, reveals capture dates after one answer and advances after 1.8 seconds; tapping the result pauses it and shows Next. Shorter games have an accurate score denominator. Browser modified dates are never used as quiz answers.

Adventure review keeps one navigation model — scroll to browse, swipe to discard — with centered Favorite and Share, a separate trashcan, an original-order moving progress rail, and progressive instructions on your actual photographs. Steps persist, can be skipped, and can be replayed from Help. The original total stays fixed and discarded photos keep their slot, faded. The discard flight shrinks evenly along its curved path and respects reduced motion; review interactions have no haptics. Discarding the final forward photo completes after its flight, even when earlier photos remain. The pager only loads nearby review photos. Live Photos display as stills in review. On iOS and Android, Settings → Autoplay videos in review starts the active local video in the review feed. A tap is required for cloud-only videos and full-screen video previews. See [review verification and platform limits](docs/PHOTO_REVIEW_QA.md).

Screenshot policy depends on the Adventure: On This Day includes all eligible screenshots/videos; Surprise Me and Hidden Corners prefer ordinary photos/videos with roughly at most 20% screenshots when possible, relaxing to fill a set. Yearbook and Time Capsule exclude screenshots by default. Screenshot Sweep uses only screenshots; All Photos and duplicate/cleanup workflows include them under existing criteria. Pit Stops remain screenshot-free. Started snapshots retain their history and date reviews append newly eligible IDs. Screenshot detection uses iOS PhotoKit subtypes and Android MediaStore directory/album metadata, not image dimensions or filenames; exported/moved images without identifying metadata cannot always be recognized.

Which Came First? keeps two stable photo targets side by side, with dates below them and bounded pinch/pan zoom. Answer input and score submission lock once per round. Paused results remain paused across background/foreground; all obsolete timers cancel on exit.

In the browser, choose **Choose photos** on Home to select files. Browser files are kept in IndexedDB locally and their dates are file-modified dates; photos picked together may share a date, but remain separate photos in Adventures.

Classic timed sessions remain available from Settings. Explore offers direct photo collections and Smart Clean; Progress provides the deletion queue. Home resumes the most recently active unfinished experience without listing every saved session. Featured offers can contain as few as three eligible photos; chosen adventures can be smaller, without padding.

## Photomosaic Lab

**Settings → Developer tools → Photomosaic Lab** opens the iPhone experiment in authorized development or opted-in staging builds. Use a fresh native build through Draftbit Publishing for the PhotoKit renderer and zoom viewer. Use TestFlight for a physical iPhone with an opted-in STAGING build (`EXPO_PUBLIC_PICTOPIA_DEV_TOOLS=enabled`). The browser shows the build requirement. The lab uses the existing native Expo module and PhotoKit.

Each run evaluates four Pictopia pastel scenes on a 32 × 24 grid. The matcher compares thumbnail colors in OKLab, including lightness, and penalizes nearby and frequent repeats. Natural and Soft color share the tile placements. Soft color makes bounded per-channel adjustments to the photo pixels. The full sample uses the visible stills currently accessible to PhotoKit, including Live Photo stills and screenshots. Limited access restricts the sample. Local caches store versioned color profiles, and temporary mosaics are removed when leaving the lab. Assets requiring iCloud downloads can be skipped. Photos, identifiers, and diagnostics stay on-device unless you explicitly share the counts and timings.

To measure a device, run Full library once and then repeat it for a warm-cache run. Compare the requested subset sizes and open all four scenes to record render times for each. Compare both treatments, pinch far enough to see the individual thumbnails, and tap tiles to check the source photos. Share run diagnostics reports analysis and matching times, render time for both treatments, cache hits, unavailable photos, and sampled app-wide resident memory. Host tests use numeric color profiles to check placement and ranking across all five sample sizes. Image quality, gestures, and end-to-end performance require the iPhone run.

## Smart Sessions

Classic timed sessions (from Settings) offer Quick Wins (screenshots and easy candidates), Memory Lane (older unreviewed memories), and Best of the Bunch (validated Pro scan groups with a suggested keeper). Choose 2, 5, or 10 minutes for a bounded batch of up to 12, 30, or 60 items. Quick Wins and Memory Lane remain free; Best never substitutes unrelated photos for missing scan results.

## Vertical Explore prototype

The original prototype route (`/vertical-explore` without an Adventure) is a free, isolated experiment with up to 200 accessible still photos in a fixed newest-first snapshot. Swipe up to see the next photo without a keep decision; swipe left or right for a provisional experimental discard, which removes the photo from the feed (also when scrolling back) while the rest keep their original order. Tap the photo or Undo to bring back the latest discard, as often as you like: it returns to its original place, from the side it left by, and is shown. Previous revisits. Progress, marks and up to 200 undoable discards persist locally. Restoring an individual photo in Review Discards puts it back in the feed and removes its undo entry; Restore All clears undo history while preserving progress. Restart clears experiment state and replays the same IDs, including unavailable ones. Videos are excluded; Live Photos display stills. Photos already in the standard deletion queue or deletion journals are excluded at selection. The experiment never writes production decisions, copies native originals, uploads photos, or invokes device deletion. Its own collection and full-screen viewer expose only restoration.

The photo accessibility wrapper stays materialized (`collapsable={false}`) to keep the gesture view’s native ancestry stable when a scrolled-to photo becomes active. A fixed-height, vertically paged FlatList places photos in adjacent clipped page slots and keeps a small neighboring render window. Native scrolling provides upward/downward dragging, interactive peeking and release snapping. Native horizontal pans recognize simultaneously with the scroll recognizer, with ±12 pt axis arbitration. Once horizontal intent activates, a shared UI-thread flag holds vertical scrolling until release; page claiming uses the captured native scroll offset and stops residual motion without an animated snap. Vertical-intent failures never enqueue a card reset. While you hold a photo sideways it follows your thumb, tilts toward the side you drag it, and shows a Delete label on the uncovered side; either direction discards. Vertical paging behaves like a social feed: the page you land on is shown immediately and saved in the background in order, so rapid flicks and peeks are never blocked or pulled back. Only a sideways discard briefly holds input while the photo flies out; the discarded card is then removed in place and the next photo slides up into its slot (the previous one slides down when none follows), so the feed never shifts under your finger. Identity is the stable photo ID, never a list position. Canceled gestures create no decisions. Next works during image loading; photos advanced before loading or unavailable at the time are separately counted rather than described as explored. Reduced-motion settings shorten motion through Reanimated’s system setting. Browser testing uses user-selected local files. Its pager supports mouse/touch vertical dragging and held peeks on the same scroll surface, with distance/velocity release snapping; wheel/trackpad scrolling remains available. Pointer intent locks to one axis; only vertical drags hold the feed, through their release snap. Bounded DOM polling releases the drag lock if the browser omits its final scroll event or interrupts smooth scrolling. Native gesture feel, iCloud handling, and lifecycle behavior require physical-device verification through Draftbit Publishing; see [the iPhone test checklist](docs/VERTICAL_EXPLORE_QA.md).

## Native application

Device deletion is verified item by item and journaled so an interrupted deletion is re-checked on the next launch; with limited photo access, items Pictopia can no longer see are never reported as deleted without proof. Use Draftbit **Publishing** for native builds. Expo Go does not contain the custom `PictopiaAnalysis` module or Expo IAP's native purchase implementation. The configured minimums are iOS 15.1 and Android 7.0 / API 24, subject to final build verification and maintained Expo support.

- `app/(tabs)/`: Home, Explore, Progress; Swipe, Smart Clean and the legacy Settings redirect stay hidden. Settings is a separate root screen.
- Other routes: onboarding, preview, deletion queue, comparison, paywall, statistics, help, legal disclosures.
- `services/`: platform media, storage, analysis, and purchase adapters; serialized repository mutations.
- `lib/pictopia/`: typed models and deterministic review/analysis logic.
- `modules/pictopia-analysis/`: autolinked Swift/Kotlin local module for streaming original-file SHA-256, tiny-image difference hashes, Laplacian variance, metadata, cancellation, and battery/thermal/memory scan checks.
- Native SQLite schema version 1; browser IndexedDB schema version 1. Legacy database names and hash boundary markers stay stable to preserve existing data after the Pictopia rename. No cleanup backend or user account is needed.
- Theme colors and typography live in `theming/themes/`; UI uses NativeWind and the existing Lucide wrapper.

Photos are referenced, not copied, on native devices. Browser selections are stored locally to support resuming. Adventure hearts update native Photos favorites on iOS and device MediaStore favorites on Android 11+, with system authorization and verification. Android MediaStore favorites do not guarantee Google Photos cloud synchronization. Browser/older Android native favorites are unsupported; classic review’s app-local favorites remain separate. Native sharing uses original-quality temporary iOS exports or authorized Android content URIs; Live Photos share their still resource. Temporary iOS exports are removed after the share sheet dismisses, with crash remnants removed on the next share. Native favorites/sharing need a new Publishing build and real-device validation. Live Photos display their still image; iOS original-content hashes include the paired video. iOS Live Photo motion playback uses a native PhotosUI view and still needs device verification.
